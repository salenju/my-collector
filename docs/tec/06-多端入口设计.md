# 06 · 多端入口设计

PRD 中"方便地在浏览器中记录链接"被确认为要做 **4 个入口**。本文件定义它们各自的能力边界、实现方式与复用关系。

## 1. 入口总览与分工

| 入口 | 触发方式 | 元信息能力 | 离线能力 | 实现成本 | 交付阶段 |
| --- | --- | --- | --- | --- | --- |
| **A. 网页应用** | 打开 URL，手动粘贴 | 需代理（§4） | 完整（Dexie） | 低 | M1 |
| **B. Bookmarklet** | 点浏览器书签 | **页面内直接读**（无 CORS 问题） | 无（跳转到应用后由应用负责） | 极低 | M5 |
| **C. Chrome 扩展** | 点扩展图标 / 右键菜单 / 快捷键 | **扩展内直接读**（无 CORS 问题） | 直接请求 GitHub，失败存草稿 | 中 | M5 |
| **D. PWA 分享目标** | 手机分享菜单 → 满天星 | 依赖分享来源携带的 title/text/url | 同 A（离线也能落本地） | 低 | M4 |

**设计原则**：四个入口不重复实现同步逻辑——B/D 本质是"把参数交给应用"，
C 复用 `@my-collector/core` 的数据层（同一套读写与提交逻辑）。

## 2. Bookmarklet（书签小工具）

### 2.1 生成方式

设置页/关于页提供「书签小工具生成器」：

```
[拖我到书签栏]  ← 一个 draggable 的 <a>，href 为生成好的 javascript: 代码
[复制代码]
```

生成逻辑（`services/bookmarklet.ts`）：

```ts
function buildBookmarklet(appBaseUrl: string): string {
  const code = `(function(){
  var u = location.href;
  var t = document.title || '';
  var d = '';
  var m = document.querySelector('meta[name="description"],meta[property="og:description"]');
  if (m) d = m.getAttribute('content') || '';
  var sel = String(window.getSelection ? window.getSelection() : '');
  var base = ${JSON.stringify(appBaseUrl)};
  var q = 'url=' + encodeURIComponent(u)
        + '&title=' + encodeURIComponent(t)
        + '&excerpt=' + encodeURIComponent(d.slice(0, 500))
        + '&content=' + encodeURIComponent(sel.slice(0, 2000))
        + '&source=bookmarklet';
  window.open(base + 'new?' + q, 'my-collector', 'width=560,height=680');
})()`;
  return 'javascript:' + encodeURIComponent(code);
}
```

- 点击后**弹出一个小窗口**打开应用的 `/new`，参数已预填；用户选标签后保存即可。
- 用户若在页面里选中了一段文字，会一并带过去（很符合"碎片信息记录"的场景）。
- 应用若已有登录（Token 在 IndexedDB 中），弹窗内无需再次认证。

### 2.2 关键设计取舍

| 取舍 | 决定 | 原因 |
| --- | --- | --- |
| 为什么用 `window.open` 而不是直接 POST 到应用 | 静态站点无常驻接口可接收 POST；且 `window.open` 在用户点击手势内不会被拦截 | 简单、无跨域问题 |
| 为什么不注入脚本到目标页面 | 部分站点 CSP 会阻断 `javascript:` 注入的脚本执行 | 只做"读 DOM 属性 + 打开窗口"，最兼容 |
| 为什么读 `og:description` 而不是抓页面正文 | 同步读取、零延迟、无网络请求 | 只为了预填，精确度足够 |
| 弹窗被拦截怎么办 | 代码里 `var w = window.open(...); if(!w) location.href = ...` 降级为当前标签页跳转 | 兜底 |
| 长 URL 超长（>2000 字符） | `content`/`excerpt` 截断到 500/2000 字符 | 避免 URL 长度限制 |

### 2.3 局限与说明（写进帮助页）

- 在 `chrome://`、扩展商店、本地 `file://` 等页面无法运行。
- 部分站点（如 GitHub 的部分页面）CSP 较严，可能只能拿到 URL 和标题，属正常降级。
- iOS Safari 的书签不易拖拽，建议 iOS 用户用 PWA 分享目标或直接粘贴。

### 3.1 manifest 片段

```json
{
  "name": "满天星",
  "short_name": "满天星",
  "start_url": "/my-collector/",
  "scope": "/my-collector/",
  "display": "standalone",
  "theme_color": "#3b82f6",
  "background_color": "#ffffff",
  "icons": [
    { "src": "/my-collector/icons/192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/my-collector/icons/512.png", "sizes": "512x512", "type": "image/png" },
    { "src": "/my-collector/icons/maskable.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
  ],
  "share_target": {
    "action": "/my-collector/share",
    "method": "GET",
    "params": { "title": "title", "text": "text", "url": "url" }
  },
  "shortcuts": [
    { "name": "新建笔记", "url": "/my-collector/new?type=note" },
    { "name": "搜索",     "url": "/my-collector/?focus=search" }
  ]
}
```

### 3.2 落地页 `/share` 的处理

```
GET /my-collector/share?title=...&text=...&url=...
  1. ShareView 解析 query
  2. 若 url 为空但 text 里含 URL（微信/微博分享常见）→ 用正则从 text 中提取首个 http(s) URL
  3. 将 text 中剩余内容作为 content（去掉已提取的 URL）
  4. 跳转 /new 并预填，source='share'
  5. 用户在应用内确认标签 → 保存（离线也可保存）
```

> 因为用 `GET`，Service Worker 已缓存的 shell 可以直接处理该导航；
> 首次安装未预热 SW 时由 `404.html` 兜底（见 01 文档 §6）。

### 3.3 平台差异（必须写进帮助页，避免用户困惑）

| 平台 | 支持度 | 说明与替代方案 |
| --- | --- | --- |
| Android Chrome / Edge | ✅ 完整支持 | 分享菜单里会出现「满天星」 |
| iOS Safari | ❌ 不支持 `share_target` | 替代方案：①直接粘贴到 PWA；②用「快捷指令(Shortcuts)」创建一个"记录到满天星"动作，打开 `/new?url=...`；③从 Safari 分享菜单复制链接再粘贴 |
| 桌面 Chrome | ⚠️ 部分支持 | 主要用于「安装到桌面 + 独立窗口」 |
| 微信内置浏览器 | ❌ | 提示"请在浏览器中打开" |

> iOS 快捷指令方案会在帮助页给出逐步配置说明（约 5 步），成本低于做扩展。

## 4. 网页元信息抓取链路（D10）

### 4.1 分层策略

```
输入 URL
  ├─ L0：来源已自带元信息（bookmarklet / 扩展 / share target）
  │      → 直接使用，不发起任何抓取请求（最快、零隐私风险）
  ├─ L1：用户在设置里配置了自建代理（customUrl）
  │      → GET {customUrl}?url={encoded}
  ├─ L2：默认公共代理链（顺序尝试，各带 6s 超时）
  │      ① https://r.jina.ai/{url}                    → 响应首部含 Title / Description（Markdown 文本）
  │      ② https://api.allorigins.win/raw?url={url}   → 原始 HTML，前端解析 og:/<title>
  └─ L3：全部失败或超时
         → 字段留空，状态行提示"⚠️ 自动抓取失败，请手动填写"
         → 不阻塞保存；条目 `metadata.fetchFailed = true` 供后续"批量补全"（a2）
```

### 4.2 解析规则（L2-② 走 HTML 时）

解析优先级（前端用 `DOMParser` 解析，不用正则匹配 HTML）：

| 字段 | 取值优先级 |
| --- | --- |
| title | `og:title` → `twitter:title` → `<title>` |
| excerpt | `og:description` → `name=description` → `twitter:description`，截断 500 字符 |
| favicon | `link[rel~="icon"]` 的 href（相对路径用 URL 解析补全）→ 否则 `{origin}/favicon.ico` |
| 站点名 | `og:site_name` → 域名 |

**安全注意**：解析出来的内容一律**当纯文本**使用，不插入 DOM 的 `innerHTML`，
过滤 `javascript:`/`data:` 开头的 favicon URL（见 08 文档 §3）。

### 4.3 交互细节

| 细节 | 设计 |
| --- | --- |
| 触发时机 | URL 输入框 `paste` 后 200ms（等用户粘贴完成）或 `blur` 时；也可手动点「抓取标题」按钮 |
| 不覆盖用户输入 | 字段有"脏标记"时不覆盖；干净字段才填充 |
| 并发与去重 | 同一 URL 5 秒内不重复抓取；同时最多 2 个抓取请求 |
| 超时 | 6s 硬超时（`AbortController`），超时即降级 |
| 取消 | 用户保存或离开页面时 `abort()` 未完成的请求 |
| 缓存 | 抓取结果按 URL（去 fragment）缓存在 `settings`→ 单独 `metadataCache` 表，TTL 24h，避免重复请求第三方 |
| 进度提示 | 状态行文字 + 骨架屏，不用阻塞式 loading 遮罩 |
| 全局开关 | 设置里可关闭；关闭后直接进入 L3（手动填写） |

### 4.4 隐私边界（必须显式告知）

- 默认使用的公共代理（`r.jina.ai`、`api.allorigins.win`）会**看到你收藏的 URL**。
- 设置页在该开关旁明确标注：
  > "开启后，粘贴的网址会发送给第三方抓取服务（r.jina.ai）以获取网页标题。若你介意，可关闭此开关，或填入自建代理地址。"
- 抓取请求**不携带任何 Token / 身份信息**（只有 URL），且与 GitHub 请求是两条完全独立的链路。
- 抓取失败/关闭时功能完整，仅需手填标题。

### 4.5 自建代理参考实现（Cloudflare Worker，可选）

> 只在你愿意承担"一个小后端"时才用；免费额度足够个人使用。

```js
// Cloudflare Worker：GET /?url=<encoded>
export default {
  async fetch(req) {
    const url = new URL(req.url);
    const target = url.searchParams.get('url');
    if (!target) return new Response('missing url', { status: 400 });
    const u = new URL(target);
    if (!['http:', 'https:'].includes(u.protocol)) return new Response('bad protocol', { status: 400 });

    const res = await fetch(u.toString(), {
      headers: { 'user-agent': 'Mozilla/5.0 (compatible; my-collector/1.0)' },
      redirect: 'follow',
    });
    const html = (await res.text()).slice(0, 512 * 1024); // 只取前 512KB

    const pick = (re) => (html.match(re)?.[1] ?? '').trim();
    const decode = (s) => s.replace(/&amp;/g, '&').replace(/&lt;/g, '<').replace(/&gt;/g, '>')
                            .replace(/&quot;/g, '"').replace(/&#39;/g, "'");
    const meta = (p) => pick(new RegExp(`<meta[^>]+(?:property|name)=["']${p}["'][^>]+content=["']([^"']*)`, 'i'));

    const out = {
      title: decode(meta('og:title') || meta('twitter:title') || pick(/<title[^>]*>([^<]*)/i)),
      excerpt: decode(meta('og:description') || meta('description') || meta('twitter:description')).slice(0, 500),
      siteName: decode(meta('og:site_name')),
      favicon: (() => {
        const h = pick(/<link[^>]+rel=["'][^"']*icon[^"']*["'][^>]+href=["']([^"']+)/i);
        try { return h ? new URL(h, u).toString() : `${u.origin}/favicon.ico`; } catch { return `${u.origin}/favicon.ico`; }
      })(),
    };
    return new Response(JSON.stringify(out), {
      headers: {
        'content-type': 'application/json; charset=utf-8',
        'access-control-allow-origin': '*',   // 允许 Pages 域名跨域读取；可收紧为你的 Pages 地址
        'cache-control': 'public, max-age=3600',
      },
    });
  },
};
```

应用侧只需在设置里把「元信息抓取」切换为 `custom` 并填入 Worker 地址，前端代码无需改动
（响应结构与前端解析器约定一致：`{ title, excerpt, siteName, favicon }`）。

## 5. Chrome 扩展（MV3）

### 5.1 结构

```
packages/extension/
├── manifest.json
├── vite.config.ts                 # 多入口：popup.html / sidepanel.html / options.html / background.ts
└── src/
    ├── background/index.ts        # Service Worker：右键菜单、快捷命令、开侧边栏
    ├── popup/                     # Vue3 + Tailwind 的轻量浮窗（工具栏图标入口）
    ├── sidepanel/                 # 右侧侧边栏入口（右键菜单 / Alt+Shift+S），见 §5.6
    ├── options/                   # PAT + 仓库配置（与 Web 设置页同构，复用组件思路）
    └── shared/
        ├── CollectForm.vue        # popup 与 sidepanel 共用的收藏表单（避免两套 UI 漂移）
        └── storage.ts             # chrome.storage.local 适配 core 的 settings 读写
```

### 5.2 manifest 关键字段

```json
{
  "manifest_version": 3,
  "name": "满天星 · 一键收藏",
  "version": "1.0.0",
  "permissions": ["activeTab", "scripting", "storage", "contextMenus", "sidePanel"],
  "host_permissions": ["https://api.github.com/*"],
  "action": { "default_popup": "popup.html", "default_icon": { "16": "icons/16.png", "48": "icons/48.png" } },
  "side_panel": { "default_path": "sidepanel.html" },
  "background": { "service_worker": "background.js", "type": "module" },
  "options_page": "options.html",
  "commands": {
    "quick-save": { "suggested_key": { "default": "Alt+Shift+S" }, "description": "收藏当前页面" }
  },
  "externally_connectable": { "matches": ["https://salenju.github.io/*"] }
}
```

| 权限 | 为什么需要 | 说明 |
| --- | --- | --- |
| `activeTab` | 点击时读取当前标签页 URL/标题 | 不申请 `<all_urls>`，**只在用户主动点击时**获得权限，隐私友好 |
| `scripting` | 读取当前页 `<meta name="description">` | 配合 `activeTab` 使用；比 `<all_urls>` 干净得多 |
| `storage` | 存 PAT 与配置 | `chrome.storage.local`（+ `session` 传递面板上下文，见 §5.6） |
| `contextMenus` | 右键「收藏到满天星」 | 可选功能，但体验好 |
| `sidePanel` | 右侧侧边栏形态 | 需 Chrome ≥ 114；`sidePanel.open()` 需 ≥ 116，`minimum_chrome_version` 已是 116 |
| `host_permissions: api.github.com` | 调用 GitHub API | 只声明这一个域 |

> **不申请** `<all_urls>`、`history`、`bookmarks`。这些权限会触发商店严格审核且无必要。
> `tabs` 是否申请取决于 §5.6.1 的开放决策（默认方案不需要）。

### 5.3 Popup 交互

```
┌─────────────────────────────────────────────┐
│ 满天星 · 收藏                        [⚙️]   │
├─────────────────────────────────────────────┤
│ 标题 [当前页面标题（可编辑）          ]      │
│ 网址 https://example.com/...        [复制]   │
│ 备注 ┌─────────────────────────────────┐    │
│      │                                 │    │
│      └─────────────────────────────────┘    │
│ 标签 [#技术 ×] [#React ×] [+ 添加…]         │
├─────────────────────────────────────────────┤
│ 已收藏过（2 小时前）  [打开原条目]            │  ← 重复检测提示
├─────────────────────────────────────────────┤
│                  [取消]  [保存 ⌘Enter]      │
└─────────────────────────────────────────────┘
```

**保存链路**
```
popup 打开
  ├─ chrome.tabs.query({active:true,currentWindow:true}) → 拿 url / title
  ├─ chrome.scripting.executeScript 读页面 meta description / icon（失败则留空）
  ├─ 查重：拉取本地缓存（chrome.storage 中的轻量索引，最近 500 条 url 的集合）
  └─ 用户点保存
       └─ 调 core 的 repository.commitItem()
            ├─ 成功 → popup 显示 ✅，1.2s 后自动关闭
            ├─ 失败（网络/冲突）→ popup 内显示错误 + 保留表单 + [重试]
            └─ 草稿持久化到 chrome.storage.local（防止 popup 被关闭丢内容）
```

**为什么不给扩展做完整离线队列**：Service Worker 会被浏览器随时终止，在 SW 里维护
跨会话的 outbox + 退避重试会让复杂度陡增。扩展的使用场景是"用户主动点击、当时大概率在线"，
因此采用「直连提交 + 失败保留草稿」的轻量模型即可，与 Web 端的离线队列形成明确分工。

> 上图的"1.2s 后自动关闭"只适用于 popup。右键菜单与快捷键原本开的 420×620 浮窗
> （`windows.create({type:'popup'})`）已由 §5.6 的侧边栏取代。

### 5.4 扩展与 Web 的数据一致性

| 项 | Web | 扩展 | 说明 |
| --- | --- | --- | --- |
| 数据层 | `@my-collector/core` | `@my-collector/core` | **同一份代码**，同一套合并/分片/原子提交逻辑 |
| PAT 存储 | IndexedDB | `chrome.storage.local` | 各自独立（Q/D14） |
| 本地缓存 | Dexie 全量快照 | `chrome.storage` 轻量索引（最近 500 条 url+title） | 扩展不需要完整离线能力 |
| 冲突 | Web Locks + CAS | 直接 CAS | 冲突时弹出提示"数据已更新，请重新打开扩展" |

**一键同步 PAT（a2）**：Web 页面通过 `chrome.runtime.sendMessage(EXTENSION_ID, {type:'sync-token', token})`
把 Token 推给扩展（依赖 `externally_connectable` 白名单）。需在 Web 端检测 `window.chrome?.runtime?.id` 是否可用。
v1 先手填两次（在扩展 options 页），把这条优化留到 a2。

### 5.5 打包与分发

- `release-extension.yml`：push `ext-v*` tag（或手动触发）→ `pnpm build:ext` →
  校验 manifest/入口文件齐备 → 打包 `extension.zip` → 创建 GitHub Release 附件。
- 因为只自己用，**不上架 Chrome Web Store**（省去审核与开发者账号费用），
  通过 `chrome://extensions` → 开发者模式 → 「加载已解压的扩展程序」安装，
  或下载 Release 里的 zip 解压后加载。
- 代价：无自动更新。帮助页说明"更新方式：重新下载新版本 zip 替换目录后点刷新"。

### 5.6 侧边栏形态（Side Panel）

**动机**：右键菜单与快捷键原本开一个 420×620 的独立浮窗，切页即丢、还得手动关。
改成 Chrome 原生侧边栏：停靠当前窗口右侧，切标签/刷新都不关闭，且是扩展自己的 origin。

**为什么不是"注入到页面里的抽屉"**：
1. 注入的 DOM 运行在宿主页面的 origin，读不到 Web 版 `salenju.github.io` 的 IndexedDB；
   MV3 下 content script 的 `fetch` 受页面 CORS 限制，打 api.github.com 必须绕回 SW，
   而本项目刻意把提交逻辑放在 SW 之外（原因见上）；
2. 宿主页面的 `frame-ancestors` / X-Frame-Options 会拦掉内嵌 iframe（Web 站自身在 08 文档里就受限）；
3. `chrome://`、扩展商店、PDF 阅读器等页面根本无法注入。

**入口分工**（两套外壳、一份表单）

| 触发方式 | 打开形态 |
| --- | --- |
| 点工具栏图标 | 仍是 `popup.html` 轻量浮窗（`action.default_popup` 保留） |
| 右键菜单「收藏到满天星」 | 右侧侧边栏 |
| `Alt+Shift+S` | 右侧侧边栏 |

> `default_popup` 与 `setPanelBehavior({ openPanelOnActionClick: true })` 互斥。
> 本方案保留 popup，因此**不设置**该行为。

**手势约束（关键实现细节）**
`sidePanel.open()` 只能在用户手势中调用，且**不能在 `await` 之后调用**（手势会失效）。
所以 SW 的流程必须是「先开面板，再异步取信息」：

```
右键 / Alt+Shift+S（用户手势）
  ├─ chrome.sidePanel.open({ windowId })      ← 同步调用，之前不能 await
  └─ 异步：
       ├─ readTab(tabId, url, title)          ← 此刻 activeTab 已授予，可注入读摘要/选中文字
       ├─ 写 chrome.storage.session['panel:context']
       └─ chrome.runtime.sendMessage({ type: 'panel:context', ... })  ← 面板已打开时即时刷新
```

面板 mount 时先读 `storage.session['panel:context']` 作初值，再监听 `storage.onChanged`
与 `runtime.onMessage`——避免"面板还在加载、消息已发出"的竞态。

**不做标签页跟随**（决策见 §5.6.1，选了"不加 `tabs` 权限"）

面板只在**打开那一刻**由 SW 取一次页面信息并交给它；之后切换标签页、页面内导航都不会
改动面板内容——既不会误改用户已填的表单，也不会显示"看起来是当前页但其实是旧页"的信息。

**保存后**：清空表单、显示「已保存」，面板**不关闭**——`chrome.sidePanel` 没有 close API，
只能由用户点面板右上角的 ×。因此底部不再有「取消」按钮，改为「重新读取当前页」：

- 该按钮走 SW 调 `readActiveTab()`，**只在 `activeTab` 授权仍然有效时可用**
  （即仍停在触发扩展的那个标签页、且没有发生过导航——Chrome 在导航或关闭标签页时回收授权）；
- 失效时面板显示「请从右键菜单或 `Alt+Shift+S` 重新打开面板」，而不是静默失败。

> 有意接受的副作用：连续收藏时不会自动换页，需手动点「重新读取当前页」；
> 若期间切换过标签页，则需要重新触发一次扩展（右键菜单 / 快捷键）。

**表单复用**：把 `popup/PopupApp.vue` 的表单抽为 `src/shared/CollectForm.vue`
（`mode: 'popup' | 'panel'`），两个入口各挂一层薄外壳，差异只在外层容器与底部按钮，
避免两套 UI 长期漂移。`?quick=1` 浮窗路径与 `shared/params.ts` 随之下线
（`windows.create` 不再被任何地方调用）。

**验收清单**

- [ ] 右键菜单 → 右侧面板打开，来源信息完整（URL / 标题 / 摘要 / 选中文字）
- [ ] `Alt+Shift+S` → 同上
- [ ] 点工具栏图标 → 仍是 popup，行为不变
- [ ] 切标签页 / 页面内导航 → 面板内容**不变**，且不会改动已填表单
- [ ] 保存成功 → 面板保留、表单清空、显示「已保存」
- [ ] 授权已失效时点「重新读取当前页」→ 提示重新触发扩展，不静默失败
- [ ] `chrome://`、扩展商店等不可注入页 → 降级为 URL + 标题，不报错
- [ ] 面板宽度拖到最窄（≈240px）不溢出、不出现横向滚动

#### 5.6.1 决策记录：不为"跟随"申请 `tabs`（选 B）

"跟随当前标签页"需要读取**当前那个标签页之外**的 `url` / `title`：`activeTab` 的授权只覆盖
"触发扩展时的那一个标签页"（导航或关闭标签页即回收，切走后也无法覆盖新标签）；而
`chrome.tabs.query/get` 返回的 `url`、`title`、`favIconUrl` 在**既没有 `tabs` 权限、
也没有匹配该标签 URL 的 host 权限**时是 `undefined`。因此"跟随"与 §5.2「不申请 `tabs`」直接冲突。

| 选项 | 代价 | 结果 |
| --- | --- | --- |
| A. 加 `tabs` | 安装提示多一条"读取你的浏览记录" | 域名/标题/链接可跟随；摘要与选中文字仍无法跟随（那需要注入权限） |
| **B. 不加权限（已选）** | 无 | 面板只在打开时取一次当前页，不做跟随 |
| C. 加 `<all_urls>` host 权限 | 提示"读取和更改你在所有网站上的数据"，最重 | 跟随 + 每次自动补摘要/图标 |

**为什么选 B**：这是自用工具，但权限提示会直接暴露在每次安装/更新后的 Chrome 提示里；
"跟随"带来的收益（省一次右键）远小于新增一条"读取你的浏览记录"的心理成本。
若将来确实需要跟随，按上表 A 升级即可，实现上只需在 SW 里加 `tabs.onActivated` 监听 +
维护 `storage.session` 的 context，面板侧无需改动（它本来就是订阅 context 的）。
