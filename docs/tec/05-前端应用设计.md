## 2. 路由表

| 路径 | 视图 | 说明 |
| --- | --- | --- |
| `/` | InboxView | 列表 + 搜索 + 标签侧栏；桌面三栏，移动单列 |
| `/item/:id` | ItemDetailView | 桌面为右栏抽屉（不离开列表），移动为整页 |
| `/new` | NewItemView | 支持 query 预填：`?url=&title=&excerpt=&content=&tags=a,b&source=bookmarklet` |
| `/tags` | TagsView | 标签 CRUD、重命名、颜色、使用统计 |
| `/settings` | SettingsView | PAT、仓库、抓取、同步、导出、设备名；首次引导也在此 |
| `/share` | ShareView | PWA `share_target` 落地点，解析 query → 转 `/new`（保留预填） |
| `/about` | AboutView | 使用帮助、快捷键、隐私说明、书签小工具生成器 |
| `/:pathMatch(.*)*` | NotFound → 重定向 `/` | 配合 `404.html` 兜底 |

- `createWebHistory(import.meta.env.BASE_URL)`，base 随 Vite `base` 变化，不硬编码。
- 路由懒加载（`() => import(...)`），首屏只加载 Inbox。
- `/new` 与 `/share` 支持在**未配置 Token** 时使用：内容先存本地草稿，配置完成后自动推送（不阻塞记录）。

## 3. Pinia Stores

### 3.1 `settings`
```ts
state: {
  repo: RepoConfig,                    // owner/repo/branch/dataDir
  hasToken: boolean,                   // 只存布尔，Token 明文不放进 store 内存（用时从 core 取）
  tokenExpiresAt: string | null,
  deviceId: string, deviceName: string,
  metadataFetch: { enabled: boolean; provider: 'jina' | 'allorigins' | 'custom'; customUrl: string },
  theme: 'light' | 'dark' | 'system',
  mergePolicy: 'delete-wins' | 'edit-wins',
  listDensity: 'comfortable' | 'compact',
}
```
> Token 明文**不进 Pinia state**，避免被 devtools/快照无意持久化；统一通过 `core` 的 `auth.getToken()` 取用。

### 3.2 `items`（读模型）
```ts
state:  { all: Item[], loading: boolean }
getters: {
  active,          // deletedAt === null && archived === false
  archivedOnly,
  filtered,        // 应用关键词 + 标签 + 类型（见 §4.6）
  byId,
  tagCounts,       // 各标签下条目数，用于侧栏徽标
}
actions: create / update / remove / archive / restore / bulkTag / bulkArchive
```
所有写 action 只调用 `core` 的 `repository`，**不直接碰 Dexie 或 GitHub**。

### 3.3 `sync`
```ts
state: {
  status: 'idle'|'syncing'|'synced'|'pending'|'offline'|'backoff'|'conflict'|'auth-error',
  lastSyncAt: string | null,
  pendingCount: number,
  conflictLog: ConflictEntry[],
  lastError: { kind: GhErrorKind; message: string } | null,
  backoffUntil: string | null,
}
```
订阅 `core` 的同步引擎事件（`on('state', ...)`），仅作 UI 投影。

### 4.2 列表页（InboxView）

**信息层级**（每张卡片）：
```
① 类型徽标（link 📎 / note 📝）  ② 标题（无标题则显示内容首行，灰斜体）
③ 域名 + 相对时间                 ④ 标签 chips（超出显示 +N）
⑤ 待同步角标（仅 pending 条目显示橙色小圆点）
```
- 默认排序：`createdAt` 倒序（最新在上）。
- 提供排序切换：创建时间 / 修改时间 / 标题。
- 列表数据量 > 100 时使用虚拟滚动（`useInfiniteList`），避免 2000 条时 DOM 爆炸。
- **键盘导航**：`j`/`k` 上下移动，`Enter` 打开详情，`e` 编辑，`a` 归档，`d` 删除，
  `Space` 多选（进入批量模式）。← 让"打标签、整理"变快，直达 PRD 的核心诉求。
- 空态：首次使用显示引导（"粘贴一个链接开始吧"+ 书签小工具安装提示）。

### 4.3 新建 / 编辑（NewItemView、ItemEditor）

```
┌──────────────────────────────────────────────────────────┐
│  [+ 链接] [📝 笔记]                      ← 类型切换       │
├──────────────────────────────────────────────────────────┤
│ URL   [https://............................]   [抓取标题]  │
│       状态行：✓ 已抓取标题 / ⏳ 抓取中… / ⚠️ 抓取失败，请手动填写 │
│ 标题  [React 19 新特性解读                       ]        │
│ 备注  ┌────────────────────────────────────────┐          │
│       │ 收藏原因：并发渲染的改进值得关注          │          │
│       └────────────────────────────────────────┘          │
│ 标签  [#技术 ×] [#React ×] [+ 添加标签…]                  │
├──────────────────────────────────────────────────────────┤
│                              [取消]  [保存 ⌘Enter]        │
└──────────────────────────────────────────────────────────┘
```

**关键交互**
1. **粘贴即抓取**：URL 输入框 `paste`/`blur` 后触发抓取（见 06 文档 §4）；抓取中不阻塞用户填别的字段。
2. **不覆盖已填内容**：抓取结果只填充**用户尚未编辑**的字段（用"字段脏标记"判断）。
3. **重复检测**：URL 归一化后命中已有条目 → 行内提示条（见 02 文档 §2.5）。
4. **标签即时创建**：输入不存在的名字 → 回车创建（提交时与其他文件一起原子写入）。
5. **草稿保护**：表单内容实时写入 `drafts` 表；误关页面重进可恢复；保存成功清除草稿。
6. **保存即返回**：`⌘/Ctrl + Enter` 保存，`Esc` 取消（有未保存改动时二次确认）。
7. **连续记录模式**：设置项，保存后自动清空并聚焦 URL 框（适合批量收集链接）。

### 4.4 详情页

- 桌面：右侧 380px 面板，列表保持可见（便于连续浏览）；移动：全页。
- 字段除 `id`/`createdAt`/`source` 外均可编辑，采用"点击即编辑"（inline edit）而非表单模式，降低整理成本。
- 底部信息：创建时间、最后修改时间、来源（网页/书签工具/扩展/分享）、所属分片路径。
- 操作：复制链接、在新标签打开、去 GitHub 看该分片提交历史、归档、删除（二次确认）。
- **只读模式**（远端 schemaVersion 更高）时全部控件禁用并显示原因。

### 4.5 标签管理（TagsView）

| 功能 | 说明 |
| --- | --- |
| 列表 | 标签名、颜色、使用条目数、最后使用时间 |
| 重命名 | 只改 `tags.json`（条目引用的是 ID，无需批量改写） |
| 改色 | 从预设 12 色调色板选择 |
| 合并 | 把 A 合并到 B：改写所有含 A 的条目的 `tagIds`（多分片操作 → 一次原子提交），删除 A |
| 删除 | 二次确认 + 显示"将影响 N 条记录"，摘除引用后删除 |
| 批量整理 | "清理未使用的标签"（count=0 的标签一键删除） |

### 4.6 搜索与筛选（v1 范围，D8）

```ts
// core/src/search/filter.ts —— 纯函数，输入 filter 输出 Item[]
interface ItemFilter {
  keyword: string;              // 空白则不过滤
  tagIds: string[];             // 多选，默认 OR（命中任一即可）
  tagMode: 'or' | 'and';        // a2 提供切换，v1 固定 or
  type: 'all' | 'link' | 'note';
  archived: boolean;            // false=主视图, true=归档视图
}
```

**关键词匹配规则**（零依赖、中文友好）：
1. `keyword.trim().toLowerCase()` 后，对每个条目做 `includes` 匹配；
2. 匹配字段：`title`、`content`、`excerpt`、`url`、以及**标签名**（把 `tagIds` 映射为名字再匹配）；
3. 多词用空格分隔 → **AND 语义**（每个词都要命中，可跨字段）；
4. 命中字段高亮显示（用 `split` + 文本插值，**不用 `v-html`**）。

> 排除 `deletedAt != null` 的条目（任何视图都不显示）。
> 排序：相关度（标题命中 > 内容命中）→ 修改时间倒序。
> 性能：2000 条时 `filter` 单次执行 < 5ms；用 `computed` 缓存。

**触发方式**（顶栏搜索框，`App.vue`）：输入**不做实时过滤**——输入只写本地草稿，
点输入框右侧的放大镜按钮或按回车才把关键词写入 `items.filter.keyword` 并跳回 `/`
（`⌘/Ctrl + K` 仍然只负责聚焦输入框）。草稿与 store 保持同步，
因此侧栏「清空筛选条件」等外部改动会同步清空输入框。

**搜索结果页**：复用 InboxView 的列表，顶部显示"N 条结果 · 关键词 xxx"。

## 5. 视觉与样式规范

### 5.1 设计令牌（`styles/tokens.css` → 映射到 Tailwind theme）

| 令牌 | 亮色 | 暗色 | 用途 |
| --- | --- | --- | --- |
| `bg` | `#ffffff` / `#fafafa` | `#0b0d12` | 页面背景 |
| `surface` | `#ffffff` | `#141721` | 卡片/面板 |
| `border` | `#e5e7eb` | `#262b38` | 分隔线 |
| `text` | `#111827` | `#e5e7eb` | 主文本 |
| `muted` | `#6b7280` | `#9ca3af` | 次要文本 |
| `primary` | `#3b82f6` | `#60a5fa` | 主按钮、链接 |
| `warning` | `#f59e0b` | `#fbbf24` | 待同步、限流 |
| `danger` | `#ef4444` | `#f87171` | 删除、冲突、过期 |

- 字体栈：`-apple-system, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`，16px 基准，行高 1.6。
- 圆角：卡片 12px，按钮/输入 8px，chip 999px。
- 间距：4px 基准，常用 8/12/16/24。
- 阴影：仅用于浮层（对话框/下拉），卡片用 1px 边框。
- 深色模式：`class` 策略（`document.documentElement.classList`），跟随系统 + 手动切换。
  手动切换有两个入口，读写同一份 `UiSettings.theme`，始终同步：
  ① **顶栏图标按钮**（`App.vue`，应用外壳级，不隐藏在断点后），点击按「跟随系统 → 浅色 → 深色」循环；
  ② **设置页「外观与设备」下拉**，三档任选。
- 标签颜色：12 色调色板，chip 用 `bg-{color}-50 text-{color}-700 border-{color}-200`（暗色下 `-950/-300/-800`），
  class 必须**完整字面量**写在代码里（Tailwind 无法扫描动态拼接的类名）——用映射表生成。

### 5.2 无障碍与体验底线

- 所有可点击元素 ≥ 44×44px 触控目标（移动端）。
- 浮层组件用 reka-ui 保证：焦点捕获、`Esc` 关闭、`aria-expanded`、键盘方向键导航。
- 对比度 ≥ 4.5:1；状态不只用颜色表达（配图标/文字）。
- 所有网络/同步状态有 `aria-live="polite"` 区域播报。
- `prefers-reduced-motion` 时禁用过渡动画。

## 6. 移动端适配要点

| 项 | 设计 |
| --- | --- |
| 断点 | `<768` 单列移动；`768–1023` 双栏；`≥1024` 三栏 |
| 底部 TabBar | 列表 / 标签 / 设置 / 新建（移动端替代侧栏；当前项用 `bg-brand/10` 底色块 + `aria-current="page"` 标记，只靠文字变色辨识度不够） |
| 输入 | `inputmode="url"`、`autocapitalize="off"`、`autocorrect="off"` 防止 URL 被自动大写/纠错 |
| 安全区 | `env(safe-area-inset-bottom)` 适配全面屏 |
| 键盘 | 表单底部按钮用 `sticky bottom` 贴键盘上沿 |
| 触控 | 滑动卡片右侧唤出快捷操作（归档/删除），替代 hover 菜单（a2） |
| 分享 | 见 06 文档 §3（Android 可用，iOS 需备选路径） |
