# 08 · 安全与风险

本方案的架构特点是：**前端代码完全公开，而凭据与数据都在用户自己手里**。
因此安全设计的核心不是"防互联网上的攻击者打进你的服务器"（你没有服务器），
而是 **① 管好浏览器里那把 PAT 钥匙；② 不让渲染环节被注入；③ 明确隐私边界；④ 保证数据不丢**。

## 1. 威胁模型

| 资产 | 谁可能碰到 | 攻击面 | 严重性 |
| --- | --- | --- | --- |
| **Fine-grained PAT** | 同源脚本、浏览器扩展、共用电脑的人、误提交到公共仓库 | XSS、恶意依赖、恶意扩展、截图/屏幕共享、git 误提交 | **高**：可读写你的收藏数据 |
| 收藏数据 | 与 PAT 同级别（有 PAT 就能读） | 同上；另加数据仓库被设为 Public | **高** |
| 本地 IndexedDB | 同源脚本、物理接触设备的人 | XSS；无磁盘加密 | 中 |
| 远端服务可用性 | GitHub、公共抓取代理 | 限流、服务变更/下架 | 低 |

**明确不在威胁模型内**：多租户越权（无多租户）、服务端漏洞（无服务端）、SQL 注入（无 SQL）、
DDoS（GitHub 承担）、供应链攻击中"从商店安装的恶意 *其他* 扩展"（超出可控范围，仅在帮助页提示）。

## 2. PAT 全生命周期管理

### 2.1 最小权限原则

| 项 | 设置 | 理由 |
| --- | --- | --- |
| Token 类型 | **Fine-grained**（不用 Classic） | Classic 权限以用户为粒度，会给到所有仓库 |
| 仓库范围 | Only select repositories → 仅 `my-collector-data` | 即使泄露，也碰不到你其他代码仓库 |
| 权限 | 仅 `Contents: Read and write`（+ 自动附带的 Metadata 只读） | 不需要 Issues/Workflows/Secrets/Administration/Deployments |
| 有效期 | 90 天 | 泄露后的暴露窗口有限；到期应用提醒续期 |
| 数量 | 每台设备/每个客户端可各建一个 Token（便于单独撤销） | 手机丢了只撤销那一个 |

### 2.2 存储与使用

| 阶段 | 做法 |
| --- | --- |
| 输入 | 设置页 `type="password"` + 可切换明文显示；输入框加 `autocomplete="off"`、`spellcheck="false"` |
| 存储 | IndexedDB（Web）/ `chrome.storage.local`（扩展）。**明文**，不做假加密（自欺欺人且增加复杂度） |
| 内存 | 不放进 Pinia state、不进 URL、不写 `console`、不进任何错误上报（本项目无遥测） |
| 传输 | 只发往 `https://api.github.com`，由 `Authorization: Bearer <token>` 头携带；**绝不放在 URL query**（会进浏览器历史、Referer、日志） |
| 展示 | 掩码 `github_pat_11ABC****XYZ`；复制 Token 需显式点击 |
| 清除 | 设置页「清除令牌」+ 「清除全部本地数据」（含 IndexedDB 与 SW 缓存） |
| 会话选项 | 提供「仅本次会话保存」（sessionStorage），公共电脑可用 |
| 泄露排查 | 提供「撤销并重新生成」指引 + 在 GitHub Settings → Tokens 中查看最近使用时间 |

### 2.3 明确不做的"安全措施"及理由

| 不做 | 理由 |
| --- | --- |
| 在 IndexedDB 里加密 Token（用固定密钥） | 密钥也必须存在同一浏览器，等于把钥匙和锁放一起；只增加代码量与"看起来安全"的错觉 |
| 把 Token 交给自建服务代管 | 违反"无自建后端、数据自持"的架构前提 |
| 使用 GitHub OAuth App（v1） | 需要注册 OAuth App 且回调地址固定；Device Flow 是更合适的下一步（已预留接口） |
| 自己实现"加密的数据仓库" | 会让 Git diff/历史完全不可读，损失本方案最大的优势；且密钥管理成本远超收益 |

### 2.4 前置检查清单（实施前逐项确认）

- [ ] `my-collector-data` 仓库可见性 = **Private**（若为 Public，你的收藏对全世界可见）
- [ ] PAT 权限只有 `Contents: Read and write`
- [ ] PAT 仓库范围只有 `my-collector-data`
- [ ] 前端仓库内**不存在任何** `.env` 里含 Token 的情况；`.gitignore` 包含 `.env*`
- [ ] 前端代码中 grep `github_pat_` 无任何硬编码（CI 加一条 grep 检查）
- [ ] GitHub Pages 的仓库是 `my-collector`（前端），**不是**数据仓库（否则会把数据仓库内容发布出去）

## 3. 客户端注入防护（XSS / 数据注入）

因为 Token 在浏览器里，**任何一次 XSS 都等价于 Token 泄露**，这一节的约束是强制的。

### 3.1 渲染纪律

| 约束 | 说明 |
| --- | --- |
| **禁止 `v-html`** | ESLint `vue/no-v-html` 置为 `error`。所有来自数据仓库的内容（标题、备注、摘要、标签名）一律用 `{{ }}` 文本插值 |
| 搜索高亮不用 `v-html` | 用 `Array<{text, hit}>` 分段后 `v-for` + `<mark>` 渲染（见 05 文档 §4.6） |
| 链接渲染 | `<a :href>` 前必须经 `isSafeUrl()` 校验，只允许 `http:`/`https:`；统一加 `target="_blank" rel="noopener noreferrer"` |
| favicon | 只接受 `https:` 且非 `data:`；加载失败降级为色块（`<img onerror>` 切换，不注入） |
| CSS 类名 | 标签颜色走**白名单映射表**（12 色），不把用户输入拼进 class 名 |
| 富文本 | v1 备注为**纯文本**（保留换行用 `white-space: pre-wrap`）；若要 Markdown，必须先做 sanitize，列为 a2 且默认关闭 |

### 3.2 CSP（在 `index.html` 的 meta 中声明，Pages 无自定义响应头）

```html
<meta http-equiv="Content-Security-Policy" content="
  default-src 'self';
  script-src 'self';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: https:;
  connect-src 'self' https://api.github.com https://r.jina.ai https://api.allorigins.win;
  object-src 'none';
  base-uri 'none';
  frame-ancestors 'none';
  form-action 'none';
">
```

| 指令 | 值的原因 |
| --- | --- |
| `script-src 'self'` | 杜绝内联脚本与远程脚本（**这是防 XSS 的第一道也是最重要的一道防线**） |
| `style-src 'unsafe-inline'` | Vue 的 `:style` 绑定与 Tailwind 动态样式需要；风险远低于脚本内联 |
| `connect-src` | 显式白名单 GitHub API 与所用代理；若切换为自建代理需同步更新（配置化） |
| `object-src` / `base-uri` / `frame-ancestors` / `form-action` | 收紧到最严，避免插件与 base 标签劫持 |

> 扩展侧在 `manifest.json` 中用 MV3 的 `content_security_policy.extension_pages` 声明同等策略，
> 且 MV3 本身就禁止远程代码与 `eval`。

### 3.3 数据注入（把仓库里的 JSON 当不可信输入）

虽然数据仓库是你自己的，但它是**可被手工编辑、可被其他设备/未来版本写入**的外部输入。
因此：

- 所有读取的数据必须经过 02 文档 §4 的**守卫校验**才进入 UI；
- 校验失败的数据**只跳过、不修复**（无法无损修复时）；
- 长度限制：`title ≤ 500`、`content ≤ 20000`、`excerpt ≤ 500`、`tagIds.length ≤ 50`，
  超出在读取时截断并记警告（防止一条恶意/异常数据把页面撑爆）；
- 不允许出现原型污染键：解析后过滤 `__proto__` / `constructor` / `prototype` 键。

## 4. 隐私边界（清晰、可核查）

| 数据流向 | 目标 | 携带内容 | 能否关闭 |
| --- | --- | --- | --- |
| 读写收藏数据 | `api.github.com` | 全部数据内容 + PAT | **不可关闭**（这是架构本体） |
| 抓取网页元信息 | 代理服务（默认 `r.jina.ai`） | 你粘贴的 URL | ✅ 设置页可关闭，或改为自建 Worker（06 文档 §4.5） |
| favicon 请求 | 站点自身 origin | 浏览器常规请求（含 Referer 可能暴露你的站点来源） | 可通过 `referrerpolicy="no-referrer"` 缓解 |
| 版本更新检查 | 无 | — | 本应用**不做**任何更新检查与埋点 |
| 错误上报 | 无 | — | **不接入** Sentry 等任何上报 |

**帮助页必须明确写给用户**（一句话版）：

> 满天星没有服务器。你的收藏只存在你自己的 GitHub 私有仓库里。
> 唯一的外部请求是「自动抓取网页标题」时把网址发给代理服务，可在设置里关掉。

## 5. 数据丢失与恢复

| 场景 | 后果 | 防护 |
| --- | --- | --- |
| 误删条目 | 数据消失 | 软删除墓碑 + 回收站 + Git 历史可找回 |
| 误改/覆盖 | 内容变了 | Git 历史可 diff 与回滚；冲突合并记录被覆盖的一方 |
| 浏览器清缓存 | 本地 outbox 丢失（**唯一真实风险**） | ① 有 pending 时顶栏常驻提示；② 写入 2s 内即推送；③ 提供「导出全部 JSON」 |
| 数据仓库被删 | 全丢 | 建议定期 `git clone` 到本地（见 §5.1），并在数据仓库加每周归档 Action |
| 设备丢失 | Token 泄露风险 | 到 GitHub 撤销该 Token（最小权限下影响面仅一个数据仓库） |
| 应用 bug 提交坏数据 | 数据损坏 | 数据仓库加 validate Action（07 文档 §3.3）+ 写入前后双重校验 + Git 可回滚 |

### 5.1 备份建议（写进帮助页）

1. **Git 本身就是备份**：每次写入都是一个 commit，理论上不会"悄悄丢数据"。
2. **本地镜像**：每周 `git clone --mirror git@github.com:salenju/my-collector-data.git`（一条命令）。
3. **自动归档**：在数据仓库加一个每周 Action，把 `data/` 打包成 zip 挂到 Release（AI方案 §8.2 的建议，建议采纳）。
4. **导出成品**：设置页「导出全部 JSON」得到单文件，可随时导入回来（导入为**合并**语义，不覆盖）。

## 6. 依赖与供应链

| 措施 | 说明 |
| --- | --- |
| 依赖数量克制 | 运行时依赖控制在 10 个以内（vue / vue-router / pinia / dexie / @octokit/core / nanoid / dayjs / reka-ui / lucide-vue-next / vite-plugin-pwa） |
| 不使用 CDN | 所有依赖打包进产物，避免第三方 CDN 被投毒 |
| 锁文件提交 | `pnpm-lock.yaml` 必须提交，CI 用 `--frozen-lockfile` |
| 自动升级提醒 | 开启 Dependabot（仅提醒，不自动合并） |
| 人工审查 | 引入任何新依赖前，评估"是否能用 30 行自己写"（例如并发限流 `mapLimit` 就自己写，不引 p-limit） |
| 构建产物核对 | 上线前 `grep -r "github_pat_" dist/` 必须无结果 |

## 7. 浏览器与平台边界（诚实告知用户）

| 限制 | 影响 | 说明位置 |
| --- | --- | --- |
| IndexedDB 明文存储 | 共用电脑上他人可通过 devtools 读到 Token | 设置页提示 + 提供"仅本次会话"选项 |
| 隐私/无痕模式下 IndexedDB 可能被限制 | 刷新即丢 | 检测到不可持久化时警告"当前处于隐私模式，数据不会保留" |
| iOS Safari 不支持 PWA share_target | 手机分享体验受限 | 帮助页提供快捷指令方案 |
| 部分站点 CSP 阻断 bookmarklet | 只能拿到 URL/标题 | 帮助页说明 |
| 浏览器扩展权限变更 | 新版本可能需重新授权 | Release 说明中标注 |
| 出口网络（部分地区访问 GitHub 不稳） | 同步失败 | 离线模式可正常使用，恢复后自动重试 |

## 8. 实施前的安全评审清单

在开始写代码前，请确认以下每一条都被接受（这些都是**有意识的取舍**，不是疏漏）：

- [ ] 接受 IndexedDB 明文存 PAT，并用"最小权限 + 90 天过期 + 严格 CSP"作为补偿控制
- [ ] 接受默认抓取代理会把 URL 发给第三方（或改为自建 Worker / 关闭该功能）
- [ ] 接受数据总量受单文件大小与分片数量约束（个人规模下无实际影响）
- [ ] 接受"无自动更新"（扩展不上架商店，需手动替换）
- [ ] 接受冲突自动合并采用 **LWW + 删除优先**，并知道可切换为"编辑优先"
- [ ] 接受数据库是"你自己的 GitHub 账号"——**账号安全即数据安全**（强烈建议开启 2FA）
